# ALIGNMENT - 前端界面与后端优化

## 一、原始需求

用户要求完成以下四项工作：

1. **前端用户界面（问答交互）**：构建基于Web的问答对话界面，用户可输入问题、查看答案和来源追溯
2. **管理员界面（上传更新知识库）**：提供管理后台，支持文档上传、知识库重建等管理功能
3. **后端四项改进**：
   - 添加单元测试覆盖
   - 检索并行化提升性能
   - 缓存升级为 Redis 支持分布式
   - 完善类型注解

## 二、边界确认

**技术选型决策：**

| 决策点 | 选择 | 理由 |
|-------|------|------|
| 前端框架 | Vue 3 (Composition API) | 与现有Python栈互补，中文社区活跃，轻量 |
| 构建工具 | Vite | 极速开发体验，HMR |

| 路由 | Vue Router | 问答页 / 管理页切换 |

### 3.3 后端 - 四项改进

#### 3.3.1 检索并行化
- 当前：`hybrid_retrieve()` → `search_web()` → `reranker.rerank()` 串行执行
- 改进：向量检索和BM25检索在EnsembleRetriever内部已通过LangChain并行，但网络检索仍在本地检索之后串行
- 方案：使用 `asyncio.gather` 将 `hybrid_retrieve` 和 `search_web` 并行执行

#### 3.3.2 Redis缓存
- 当前：[utils/cache.py](file:///Users/jinmu/Desktop/金木/my-project/工程质检RAG系统/app/utils/cache.py) 纯内存缓存
- 改进：新增 Redis 缓存后端，保持相同接口，不可用时降级为内存缓存
- 配置项：`REDIS_URL`（可选，不配置则用内存缓存）

#### 3.3.3 单元测试
- 覆盖模块：chunker, query_rewriter, reranker, cache, document_loaders
- 框架：pytest + pytest-asyncio + pytest-cov
- 测试目录：`tests/`

#### 3.3.4 类型注解
- 当前多处使用 `-> object` 返回类型
- 改为具体类型：`ChatTongyi`, `DashScopeEmbeddings`, `Chroma`, `BM25Retriever` 等
- 使用 `TYPE_CHECKING` 避免循环导入

## 四、疑问澄清

基于项目现有架构和前端需求文档，以下决策已明确：

| 问题 | 决策 | 依据 |
|------|------|------|
| 前端框架选什么？ | Vue 3 + Vite | 需求文档推荐，中文社区好 |
| 是否需要用户登录？ | 不需要（任务范围外） | ALIGNMENT边界明确 |
| Redis是否必须？ | 可选（不配置则降级内存） | 兼容现有部署 |
| 文档上传格式？ | MD/XLSX/XLS（与现有一致） | 复用现有document_loaders |
| 管理员是否需要权限？ | 暂不需要 | 任务仅要求管理界面 |
| 前端是否独立部署？ | 是，开发时Vite代理到5002 | 前后端分离 |
